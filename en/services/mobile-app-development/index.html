Mobile app development

A mobile product needs more than a collection of screens. People must be able to start a task, understand its status and recover when something interrupts it. PREJ develops Android and iOS applications with React Native and Expo, connecting the mobile experience to the APIs and operational tools behind it. We begin with the people using the product and the real conditions in which they will use it.

What we can build together

01

Design the journey around a real task

Booking a service, following an assignment or checking a status each involves different decisions. We map the important states before implementation: the first visit, an action in progress, a changed request and a completed task. That makes the scope easier to review and gives the interface a clear purpose. Permissions, account roles and the information visible to each user belong in that discussion, not as an afterthought.

02

Connect the app to the whole system

Where the product calls for them, mobile work can include maps, location, notifications and backend integration. We define which information the app reads, which actions change it and how the administrative workspace stays in step. An interface should not promise that an action succeeded before the system has confirmed it. Network interruptions and rejected requests need understandable responses and a way to continue.

03

Separate a pilot from a public release

A useful pilot answers specific questions with a limited audience. A store release adds a separate set of requirements, device checks and publishing steps. We agree which platforms and flows belong to each stage rather than treating an Android build as proof of an iOS release. Hosting, external services, app-store accounts and ongoing support are discussed explicitly for the particular project.

A scope you can review

  • A documented set of user journeys, roles and acceptance criteria.
  • Reviewable mobile interfaces connected to the agreed API flows.
  • Testing of priority journeys and a handover plan for the agreed stage.

From requirements to a working system

We first clarify the problem and the smallest useful product. We then work through interfaces and implementation in reviewable increments, checking the complete journey rather than isolated screens. The handover makes known limitations visible, so the next decision is based on evidence. You work directly with Xhevdet Ferizi on the technical direction; AI tools assist the engineering workflow, while decisions and accountability remain human.

Practical questions

Can an existing backend be used?

We start by reviewing its available interfaces, authentication, data model and limitations. Integration scope depends on what the existing system supports. If changes are needed, they should be agreed before the mobile app relies on them.

What should I bring to the first discussion?

A short explanation of the users and their main task is enough to start. Existing screens, systems, platform preferences and operational constraints help us turn that conversation into a realistic first scope.
